# Поширені запитання

## Що таке Ethereal?

Ethereal — це root-рішення на основі модуля ядра для ARM64 GKI 1.0 та GKI 2.0. Воно завантажує `ethereal.ko` із завантажувального ramdisk, не перезаписуючи kernel Image.

## Що змінює патч завантажувального образу?

- GKI 1.0: `ethereal-init`, KO та інші завантажувальні файли додаються до ramdisk образу `boot.img`; `rdinit=/ethereal-init` додається до cmdline того самого `boot.img`.
- Офлайн-патч GKI 2.0: вибирається лише один `init_boot.img`. Файли додаються до нього, штатний `/init` зберігається як `init.ethereal.bak`, а додатковий `PT_LOAD` перенаправляє точку входу ELF через завантажувач Ethereal. Відповідний `boot.img` і його cmdline не змінюються. GKI 2.0 `boot.img`, що містить лише ядро, відхиляється як окрема ціль. Direct Install і надалі патчить `init_boot` і `boot` разом в одній транзакції.

GKI 1.0 і Direct Install запускають `/ethereal-init` через `rdinit`. Офлайн-шлях GKI 2.0 входить до завантажувача, вбудованого в штатний `/init`, завантажує точний KMI-модуль через `finit_module()`, а потім переходить до початкової точки входу ELF. Штатний файл не замінюється; зняття патча відновлює його з `init.ethereal.bak`.

## Чому немає одного універсального KO?

Ядра з однаковою основною версією можуть використовувати різні Android KMI, версії символів і CRC. Ethereal збирає окремий KO для кожного підтримуваного KMI та завантажує лише однозначний збіг. Якщо точного збігу немає, система продовжує завантаження без Ethereal.
